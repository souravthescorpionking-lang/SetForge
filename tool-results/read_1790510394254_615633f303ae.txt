     1→# STNDRD Fitness — App Documentation
     2→
     3→## 1. Overview
     4→
     5→STNDRD Fitness is a mobile workout-tracking application built with Expo (React Native + Web). It guides users through structured training programs, logs every completed session to a PostgreSQL backend, tracks daily nutrition + water, streams exercise demo videos from Cloudflare R2, and surfaces progress and community activity on a dark-themed UI. The repository is a **pnpm monorepo** that co-locates the mobile client, the Express API server, an OpenAPI spec + generated client, a Drizzle DB package, shared Zod schemas, and a Vite component preview sandbox.

    92→
    93→Metro (`artifacts/mobile/metro.config.js`) proxies `/api/*` from the Expo dev server to `localhost:3000`. The middleware also strips `origin`/`referer` so the Replit iframe can load the bundle past Metro's CORS guard, and adds permissive `Access-Control-Allow-*` headers.

   159→### 5.3 Context providers
   160→
   161→#### `WorkoutContext` (`context/WorkoutContext.tsx`)
   162→
   163→Central in-memory + AsyncStorage store. Wraps the entire app.
   164→
   165→Exposed state slices:
   166→
   167→| State | Type | Purpose |
   168→|---|---|---|
   169→| `workouts` | `SavedWorkout[]` | User-saved single workouts |
   170→| `userPrograms` | `UserProgram[]` | Seed programs (Jacklete, Legacy Bro Split) + user-created programs |
   171→| `userOnDemand` | `UserOnDemand[]` | User-saved on-demand sessions |
   172→| `activeProgram` | `ActiveProgramState \| null` | `{ programId, completedSessions }` — currently active program |
   173→| `currentProgramId` | `string \| null` | Selected program in builder flows |
   174→| `buildExercises` | `BuildExercise[]` | Workout builder draft state (sets, reps, tempo, intensifier, series grouping) |
   175→| `pendingExercises` | `PendingExercise[]` | Exercises staged by Add Exercise screen, plus `pendingMode` (`new`/`replace`/`addToGroup`) and `pendingMeta` (`uid`/`groupId`) |
   176→
   177→Key actions:
   178→
   179→```ts
   180→setActiveProgram(programId)        // start a program from day 1
   181→advanceActiveDay()                  // increment completedSessions
   182→clearActiveProgram()
   183→addWorkout(w) / removeWorkout(id)
   184→addUserProgram(p) / patchUserProgram(id, changes) / removeUserProgram(id)
   185→addBuildExercises(pending) / reorderSeriesGroups(order) / updateBuildSet(...) / clearBuild()
   186→addUserOnDemand(u) / removeUserOnDemand(id)
   187→setPendingAction(list, mode, meta) / clearPendingExercises()
   188→```
   189→
   190→Persistence keys (AsyncStorage):
   191→| Key | Payload |
   192→|---|---|
   193→| `stndrd_active_program_v1` | `ActiveProgramState` |
   194→| `stndrd_jacklete_seeded_v1` | seed flag for Jacklete logs |
   195→| `stndrd_logs_seeded_v1` | seed flag for scheduled workouts |
   196→
   197→Day progression for active program:
   198→```
   199→workoutDays   = program.days.filter(d => d.type === "workout")
   200→totalSessions = workoutDays.length * program.weeks
   201→currentDay    = workoutDays[completedSessions % workoutDays.length]
   202→weekNumber    = Math.floor(completedSessions / workoutDays.length) + 1
   203→dayNumber     = completedSessions + 1
   204→// Rest days excluded from counter; program auto-clears when complete.
   205→```
   206→
   207→#### `LogsContext` (`context/LogsContext.tsx`)
   208→
   209→React-Query-backed log + schedule store. `useLogs()` returns:
   210→
   211→```
   212→logs              WorkoutLog[]       // GET /api/workout-logs
   213→logsLoading       boolean
   214→updateExerciseSets(logId, exerciseId, sets)
   215→deleteLog(id)                          // DELETE /api/workout-logs/:id
   216→scheduledWorkouts ScheduledWorkout[]   // GET /api/scheduled-workouts
   217→addScheduledWorkout(s)                 // POST /api/scheduled-workouts
   218→removeScheduledWorkout(id)             // DELETE /api/scheduled-workouts/:id
   219→```
   220→
   221→Seeding: on first launch with the flags unset, `LogsProvider` POSTs `SEED_SCHEDULED` workouts and `JACKLETE_LOGS` (Week 1–4 of the Jacklete program).

   263→
   264→- **Header**: 40 px avatar circle (initials "SP") that pushes `/profile`, title "Workout", today's full date (`Month DD, YYYY`), calendar icon top-right → `/workout-logs?view=calendar`.

   524→## 7. API Server
   525→
   526→Source: `artifacts/api-server/src/`. Stack: Express 5 + pino-http + cors + `@workspace/db` + `drizzle-orm` + `@aws-sdk/client-s3`.
   527→
   528→Boot: `index.ts` reads `PORT` (required, parsed int, >0), then `app.listen()`. `app.ts` mounts `pinoHttp`, `cors()`, `express.json()`, `express.urlencoded()`, and `/api` router.
   529→
   530→### 7.1 Endpoints
   531→
   532→| Method | Path | Handler | Description |
   533→|---|---|---|---|
   534→| GET  | `/api/healthz` | `routes/health.ts` | `{ status: "ok" }` |
   535→| GET  | `/api/workout-logs` | `workoutLogs.ts` | List logs ordered by `createdAt DESC` |
   536→| POST | `/api/workout-logs` | `workoutLogs.ts` | Insert log (client-generated id) |
   537→| DELETE | `/api/workout-logs/:id` | `workoutLogs.ts` | Delete by id |
   538→| PATCH | `/api/workout-logs/:id/exercises/:exerciseId/sets` | `workoutLogs.ts` | Replace `sets` of one exercise in a log; renumbers `setIndex` |
   539→| GET  | `/api/scheduled-workouts` | `scheduledWorkouts.ts` | List ordered by `dateISO ASC` |
   540→| POST | `/api/scheduled-workouts` | `scheduledWorkouts.ts` | Create |
   541→| DELETE | `/api/scheduled-workouts/:id` | `scheduledWorkouts.ts` | Delete (404 if none) |
   542→| GET  | `/api/nutrition-logs/:date` | `nutritionLogs.ts` | Get by ISO date (404 if not seeded) |
   543→| PUT  | `/api/nutrition-logs/:date` | `nutritionLogs.ts` | Upsert — inserts if absent, updates `updatedAt` if present |
   544→| GET  | `/api/exercises` | `exercises.ts` | List exercises from Cloudflare R2 (`cbumexerciselibrary/` folder listing) — returns `[{ id, folder, name, muscles[], instructions[] }]` |
   545→
   546→Errors return `{ error: string }` with HTTP 4xx/5xx. No auth — `cors()` permissive.
   547→
   548→`exercises.ts` notes:
   549→- Uses `S3Client` (region `auto`) against `https://${R2_ACCOUNT_ID}.r2.cloudflarestorage.com`.
   550→- `ListObjectsV2Command` with `Delimiter: "/"` to enumerate top-level folders inside `cbumexerciselibrary/`.
   551→- For each folder: `GetObjectCommand` on `Instructions.txt`, stream → string → split lines → strip numeric prefix.
   552→- Folder slugs are parsed: `Bench_Press-Chest-Triceps` → `{ name: "Bench Press", muscles: ["Chest", "Triceps"] }`.

   745→## 14. Architectural Decisions
   746→
   747→1. **Client-only program state** — `activeProgram` lives in WorkoutContext + AsyncStorage. Avoids server round-trips for a local UX concern.
   748→2. **Session counting, not calendar tracking** — `completedSessions` counts only workout sessions; rest days excluded. Avoids date math and missed-day handling.
   749→3. **Metro proxy for API** — `/api/*` proxied from Expo (5000/8080) to Express (3000). API stays a private localhost service.
   750→4. **OpenAPI is the source of truth** — never hand-write hooks; regenerate. Exception: the R2-backed `/api/exercises` is bypassing this for now (`useExercises` is hand-rolled).
   751→5. **Postgres + Drizzle** — managed Postgres; `DATABASE_URL` required at boot.
   752→6. **R2 for exercise media** — exercise videos / setup images / instructions live in Cloudflare R2 (`gym-assets-storage`). The API enumerates folders via `@aws-sdk/client-s3`; the client streams assets via `EXPO_PUBLIC_R2_BASE_URL`.
   753→7. **`programs/index.tsx` is frozen** — extend via `user-detail.tsx`, home card, context only.
   754→8. **No auth** — all data is global to the deployment.
   755→9. **Liquid Glass tab bar** — `NativeTabs` auto-detected on iOS 18+; classic blur/web bar elsewhere.
   756→10. **Seed-once flags in AsyncStorage** — `stndrd_logs_seeded_v1` and `stndrd_jacklete_seeded_v1` prevent re-seeding on every launch.
